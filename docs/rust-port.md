# Validation rule reference and Python/Rust parity notes

The generated rule table below is the reference for every `BundleValidator`
rule, and `scribe/dev/export_expected.py --render-docs` regenerates it. The
parity notes explain how the Rust validator stays identical to the Python one.

## Architecture

- `scribe-spec`: pure data (models, version gate, rule checks over in-memory
  data). No filesystem, no subprocesses, no network.
- `scribe-core`: bundle loader (UTF-8/NFC, existence, hashes, path safety),
  the `MediaProbe` trait plus the ffprobe subprocess implementation plus a
  fake for tests, orchestration, doctor checks.
- `scribe-cli`: binary `scribe-rs`; human output and exit codes match the
  Python CLI, plus `--json` (harness-only extra; the Python CLI is untouched).
- `scribe-client`: typed client for the helper's localhost API (`docs/api.md`).
- `scribe-ui`: the egui desktop app. The full-logic Rust rewrite is cancelled
  (D-147): the UI drives the packaged Python Scribe, which stays canonical.

Python is canonical: never change Python validator behavior to match Rust. A
suspicious rule gets logged and raised, never fixed in one implementation only.

## Parity levels

1. `validate` mode: same verdict plus same `(file, rule,
   message)` triples on every bundle fixture.
2. `draft`, `attribute` and `build` modes are not implemented in Rust and are
   not planned; each would need its own contract tests and expected files.


## Comparison rules (decision S15-5)

- Errors compare as a sorted list of `(file, rule, message)`; sort key is
  `(file, rule, message)`.
- `rule` ids come from the table below, assigned at export by template
  match; the exporter fails loudly on zero or double matches.
- Messages embedding parser detail (JSON syntax positions) or OS detail
  (read errors, UTF-8 decoder reports, ffprobe stderr) compare on the
  `prefix` head only; everything else compares exactly.
- Path separators normalize to `/` and the local bundle root becomes
  `<bundle>` before comparing, so Windows and Linux match.
- Expected files live under `parity/expected/` (never beside fixtures);
  probe overrides for the audio fixtures live under `parity/probes/`.

## Python rendering quirks Rust must reproduce byte-for-byte (RS2 notes)

- Version lists render with Python `list()` repr: `['1.0', '1.1', '1.2',
  '2.0']`, `['none', 'partial', 'complete']`, `['mp3', 'm4a']`,
  `[24000, 22050]`, `['narrator', 'dialogue']`.
- Block types render as a tuple: `('heading', 'para', 'quote', 'break')`.
- `sorted()` outputs render as lists: source indices `[1, 1, 3]`, chapter
  formats `mp3`.
- Floats render Python-style (`1.0`, `0.5`); dicts keep insertion order.
- `NaN`/`Inf` can never appear in a fixture: Python parses them but
  serde_json refuses them, so `GAIN-NONFINITE` is unit-tested, not fixtured.

## How to add a rule

1. Add the check to the Python validator first (canonical).
2. Add one `Rule` row to `RULES` in `scribe/dev/export_expected.py`
   (regex on the constant template part, covering fixture, `prefix` when
   the message embeds parser or OS detail).
3. Add or extend a fixture under `spec/fixtures/` so the rule fires.
4. Run the export, re-render this table, run the suites.
