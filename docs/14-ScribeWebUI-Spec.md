## 1. Goal

A local web UI over the existing Scribe library so a conversion never requires
the command line: pick a book, pick a chapter/page range, assign voices per
character with audition, run queued builds in the background with live
progress, and inspect/validate the result.

**Done when:** EPUB and PDF go from file to validated bundle, with per-character
voices, entirely through the UI, while a second build queues behind the first.

As built: met for the automated contract (upload to valid bundle without the
CLI, ranges validate, cache reuse in the counts, cast without YAML, FIFO
queueing, pause/resume, inline validate, verified transfer). The browser-closed
3-hour build, the pause/resume feel, and the end-to-end fresh-user run are user
acceptance (appendix A).

## 2. Non-goals (v1)

- No authentication, no multi-user, no remote access (binds `127.0.0.1` only).
- No Docker image (v2/v3; section 9 keeps the seams).
- No Page-view rendering, no Player features (Player stays a separate app).
- No new TTS engines, no new attribution rules (UI surfaces what Scribe does).
- No npm/build step for the frontend (section 6).

As built: all hold. Local hardening goes beyond "bind only": Host check, no
CORS, per-run token, path confinement (D-052). Docker stays a v2/v3 note.

## 3. Requirements (user brief, mapped)

1. **Range conversion.** Chapter x-to-y (EPUB chapters, PDF outline chapters)
   or page x-to-y (PDF source pages). Applies to draft, build, and the emitted
   bundle, which contains only the range. Bundle id derives from book + range
   so caches stay stable and re-runs are minimal.
2. **Per-character voices.** Full cast table: every detected speaker with a
   voice dropdown, per-row audition, speed offset, and first-person mapping.
   Writes `cast.yaml` through the validated merge path (never clobbers).
3. **Background + hardware.** Jobs run detached from the page (close the tab,
   builds continue). Progress streams back on reconnect. CPU thread count and
   GPU provider (CUDA/DML/CPU via onnxruntime) selectable per job, detected
   at startup and shown in the UI (`scribe doctor` data).
4. **Clean minimal UI.** Section 8 (Scribe design system, Operate mode).
5. **Localhost v1, Docker later.** Section 9.

As built: (1) draft is whole-book; ranges select at build/preflight; range
bundles carry `source_index` and a range-aware id under spec 1.2 (D-051). (2)
holds, with structured patch ops plus an mtime conflict guard; a UI save keeps
all hand-edited values but drops `#` comment lines (PyYAML cannot round-trip
them; flagged in the API and D-056). (3) holds with amendments: detached
processes, single FIFO, sentinel pause, device as a persisted machine setting
defaulting to `auto`; no per-job thread count (workers scrapped). (4) holds per
UI9 (D-059). (5) holds; Docker needs only mounts plus `--gpus`.

## 4. Architecture

```
browser (static HTML/CSS/JS, no framework, no build step)
  |  JSON + SSE over http://127.0.0.1:<port>
  v
scribe ui  (FastAPI + uvicorn, optional scribe[ui] extra, AGPL-clean)
  |  detached scribe build/draft/voices-sample processes + in-process copy
  v
Scribe library (extract / text / tts / audio / bundle: unchanged logic,
                extended only where section 5 requires)
```

- One server process plus one detached child per running job. The server tails
  each job's `events.jsonl` and streams it as SSE with reconnect
  (`Last-Event-ID`) and heartbeats. A native inference crash cannot take down
  the server; closing the browser (or restarting the server) never touches a
  running job; the UI reattaches and a dead-pid job reads as `interrupted`,
  resumable from cache.
- Frontend: one static page with vanilla JS + `EventSource`. No framework, no
  build step, no CDN, fully offline; system font stacks only.
- State on disk stays canonical: work dirs, `cast.yaml`, bundles, plus one
  folder per job (`job.json`, `events.jsonl`, `build.log`, `stop` sentinel).
  History is a directory scan. No database.

## 5. Backend contracts (what Scribe gained)

1. **Range selection.** `build` accepts `--chapters A-B` (also `3-5,7`) and
   (PDF) `--pages A-B`, resolving to whole covering chapters via sentence page
   provenance; combining both is rejected (`chapters-pages-exclusive`). Draft
   processes the whole book. `build --plan` (and the `plan_build()` dry run)
   prints cached vs to-render counts plus a time estimate from recent RTF.
   Out-of-range values fail with a named `{file, rule, message}` error before
   any synthesis. Full-book remains the default (no flags).
2. **Cast API.** Draft `cast.yaml` reads as structured data; five typed patch
   ops (`set_voice`, `set_speed`, `set_first_person`, `add_override`,
   `remove_override`) write through the MV5 merge/validate path atomically
   (all ops validate before any write) with an mtime guard (409 + current
   state on conflict). Audition serves cached clips; generation is a detached
   `voices-sample` job, never an inline synth.
3. **Voice inventory.** D-036 palette with per-voice locale/gender details plus
   the engine version and sample-text hash; clips cached by (voice, engine
   version, text) under `.scribe/voice-samples/`, served with immutable
   caching for versioned hits. Full engine enumeration stays deferred.
4. **Job runner.** States
   (`queued/running/paused/done/failed/cancelled` plus `interrupted` for jobs
   whose process died); progress events (chapter, sentence, cached-vs-rendered
   counts, RTF, ETA); pause/resume/cancel; single FIFO; one render per book;
   per-book lock file honored by UI and CLI; keep-awake while a job runs
   (with an opt-out setting). Drafts are jobs too (same store, same FIFO).
5. **Inspect/validate as data.** Book detail carries chapters with durations,
   cast summary, progress, validation results shaped `{file, rule, message}`;
   `POST /api/books/{id}/validate` re-runs the validator inline.

## 6. HTTP + event surface (as built; replaces the draft sketch)

Full route list with methods and 202/409 shapes is appendix B. Sketch-to-built
mapping: `GET /api/books` kept; draft-by-POST became upload-then-draft-job
(`POST /api/books/upload`); cast read/write became the five-op
GET/PUT/PATCH plus report and quotes picker; voices became the palette plus
versioned clip GET and two sample POSTs; build became `POST
/api/books/{id}/build` plus `POST .../plan` preflight; queue became `GET
/api/jobs`, one-job GET, pause/resume/cancel POSTs, and per-job SSE; bundles
became the validate POST plus transfer POST, drives GET, and open-folder POST;
settings became `GET/PUT /api/settings` (`keep_awake`, `device`).

## 7. Views (four, no more in v1)

1. **Books.** Source files (EPUB/PDF), per-book status (Drafted, Cast edited,
   Rendering with percent, Valid, On tablet) derived from files plus the job
   store, "New conversion" via drag-and-drop upload. One primary action per
   row. Empty states name the next action.
2. **Book detail.** Stepper: range picker (chapter checkboxes plus X-to-Y
   shorthand; page-range input with resolved preview for PDFs) with preflight
   panel (will-render/cached/estimate), Draft with quality report inline,
   **Cast table** (speaker, line count and minutes, voice select, audition
   play, speed, first-person toggle; overrides editor with low-confidence
   filter and re-voice counts; `cast_report.md` read-only), Build with live
   progress/RTF/ETA/cache-hit plus pause/resume/cancel, bundle card
   (duration, voices, validate badge, transfer step).
3. **Jobs tray.** All jobs with live progress, pause/resume/cancel, completion
   state, outcome plus RTF history; survives tab close (server-side jobs,
   poll/SSE resubscribe); server shutdown warns about running jobs in the log.
4. **Voices.** Audition grid: palette voices with play buttons; Regenerate
   single plus Regenerate-all; concurrent requests for the same missing clips
   coalesce to the running job (`coalesced: true`).

Settings (small panel, not a fifth view): keep-awake toggle, device select,
workspace location, `doctor` output.

## 8. Scribe design system (theme, as built)

Operate mode: scanability and consistency outrank expression. Brand lives in
precise details, not decoration.

- **Palette:** paper `#FAF7F0`, ink `#1A1714`, muted `#6B625C`, hairline
  `#E7E2D9`, one accent (oxblood `#7B2D26`, primary actions plus the "now
  building" state only). Success is sage `#5F7166` and nothing else; busy chips
  use ink. Dark mode flips the same 8 vars via `prefers-color-scheme`. All
  text pairs pass 4.5:1 (light body 16.68, muted 5.57, accent 8.74, success
  4.86, button 9.35; dark body 16.68, muted 8.20, accent 9.45, success 8.36,
  button 9.45).
- **Type:** system serif for book text and excerpts; system sans for UI;
  tabular numerals for all timings and counts. Serif scoped to the wordmark
  plus the book title.
- **Rhythm:** 8pt grid, 4px radius, hairline dividers (no card boxes), one
  elevation level (cast-conflict banner only).
- **Components (five):** table, stepper, tray, player row, chips. Everything
  else is native HTML. Toasts are tray notices, not a sixth component.
- **Rules:** no modals except confirmations; every background action shows
  progress within one second; every error names file + rule and offers the next
  step; copy conventions (`58:32`, `24.8x RTF`); no animation except progress
  and state transitions; keyboard-reachable controls; visible focus; live
  regions for progress and results.
- **Audition discipline:** one preview voice at a time (starting a second
  stops the first); cached audio replays instantly.

## 9. Ops seams (v2/v3, not built now)

- No `--host` flag by design; all views read one `api()` helper so adding a
  token later touches one file (the per-run token already flows through it).
- Work dirs, models, bundles all path-configurable (already true); `--workspace`
  roots everything, so Docker `-v` mounts need no code change; document the
  three mounts.
- GPU: device names already abstracted (`auto`/`cpu`/`cuda`); Docker needs only
  `--gpus` plus the onnxruntime build that carries the provider.
- Frontend has no build step, so the image is `python + uv sync + scribe`.

## Appendix A: acceptance checklist (user runs, spec section 9 equivalent)

From the Slice 6 plan "Done when":

1. A fresh user goes from upload to a valid multi-voice bundle without touching
   the CLI (README-tested).
2. Chapter-range and page-range renders validate, and cache reuse shows in the
   counts.
3. Cast edit, audition, override and rebuild work without hand-editing YAML.
4. A 3-hour-scale build runs with the browser closed, pauses and resumes, and
   shows sane RTF and ETA.
5. New UI tests (API, job state machine) pass alongside the existing 482, with
   no slowdown to the existing suites (automated half: 657 green, deltas are
   the new suites only; no model load).

Plus the Slice 6 definition of done: security checks tested (Host, token, path
confinement); packaged install works from a clean environment with and without
the `ui` extra; licenses verified; decisions D1-D8 logged; roadmap updated;
tagged `slice-6`.
