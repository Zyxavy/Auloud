# Repo audit, 2026-11-26 (branch feat/optimization-andriod12)

What this repo does: Scribe (Python, PC) turns ebooks into multi-voice audiobook bundles; Player (Kotlin, Android) plays them with read-along text and can also render and stream its own audio with on-device voices; scribe-rs (Rust) is a native desktop UI over the Python helper. Load assumed: one user, one PC, one old tablet (Android 7.1.1, about 1.5 GB RAM), plus the new goal of running on Android 12+ devices.

Baseline at ff7d717: Scribe `uv run pytest -x` stops at 1 failure (tests/test_build.py::test_kill_resume_identical_bundle, resumed build re-renders all 3 chapters instead of skipping 1), 55 passed before it. Rust tests could not build (no MSVC linker on this PC). Player unit tests: see the plan.

## Must fix

1. **Render notification has no channel, so rendering crashes on Android 8+ (including 12)** (player/app/src/main/java/app/auloud/player/render/RenderService.kt:L1739-L1790, L1816-L1835)
   - What this is: the render service builds its own foreground notification with `Notification.Builder(this)`; the two `SDK_INT >= 26` blocks are empty.
   - Problem: on API 26+ `startForeground` with a notification that has no valid channel fails ("Bad notification for startForeground"), so the first render tap on an Android 12 phone kills the app.
   - Fix: create one `NotificationChannel` (IMPORTANCE_LOW) behind `SDK_INT >= 26` and pass its id to the builder; delete the empty blocks.
   - If we skip it: no on-device render on any phone newer than Android 7.

2. **Default books folder and storage permission cannot work on Android 11+** (storage/BooksRootResolver.kt:L83-L98, storage/StoragePermissions.kt:L18-L28, MainActivity.kt:L401-L407, AndroidManifest.xml:L7-L8)
   - What this is: the default library is `/sdcard/Auloud`, read with `java.io.File`, gated on READ/WRITE_EXTERNAL_STORAGE.
   - Problem: with targetSdk 36, WRITE does nothing on API 30+ and READ is auto-denied on API 33+. On Android 12 `mkdirs()` fails with EACCES, the library is empty, the Wi-Fi receiver cannot unpack, and the "check storage permission" notice shows on every launch.
   - Fix: on API 30+ request no storage permission and default the root to `getExternalFilesDir(null)/Auloud` (no permission needed); keep the SAF folder picker for user folders; add `maxSdkVersion` to the two permissions. API 24-29 unchanged.
   - If we skip it: a fresh install on Android 11+ is unusable without the picker.

3. **No TTS voices on Android 11+ (package visibility)** (tts/SystemTtsDriver.kt:L70, tts/BookVoiceVersions.kt:L33-L37, AndroidManifest.xml)
   - What this is: the app lists TTS engines with `TextToSpeech.engines` and reads their package info.
   - Problem: from API 30 other apps are hidden unless declared in `<queries>`, so the engine list is empty and `getPackageInfo` throws for the default engine. Voice setup shows "no engines".
   - Fix: add `<queries>` for the `android.intent.action.TTS_SERVICE` intent (plus the battery-settings intent). Manifest only.
   - If we skip it: system-voice rendering and streaming are dead on Android 11+.

4. **Foreground services declare no type, so playback and render crash on Android 14+** (AndroidManifest.xml:L31-L50)
   - What this is: both services enter the foreground; the manifest has only FOREGROUND_SERVICE.
   - Problem: with targetSdk 34+, Android 14+ throws `MissingForegroundServiceTypeException` on first Play (Media3) and first render.
   - Fix: `foregroundServiceType="mediaPlayback"` + FOREGROUND_SERVICE_MEDIA_PLAYBACK on PlaybackService; `specialUse` + FOREGROUND_SERVICE_SPECIAL_USE + the subtype property on RenderService (no 6 hour cap, unlike dataSync). Older APIs ignore them.
   - If we skip it: not an Android 12 blocker, but the same APK crashes on 14, 15, 16.

5. **Pairing-code lockout never locks out a guesser** (receive/ReceiveServer.kt:L62-L85) (verified)
   - What this is: the Wi-Fi receiver accepts a bundle only with the 6-digit pairing code and is meant to refuse after 10 wrong tries.
   - Problem: the cap is checked only on a wrong code. After the cap the right code still passes and resets the counter, and wrong guesses past the cap skip the 1 s brake. Parallel connections make 1,000,000 codes reachable while the Receive screen is open.
   - Fix: check `badGuesses.get() >= MAX_BAD_GUESSES` first and return 429 for any code; drop the reset on success. Test: 11 wrong codes, then the right one, expect 429.
   - If we skip it: anyone on the same Wi-Fi can push files into the library.

6. **Every auto-resume leaks the TTS engines** (render/RenderService.kt:L497, L694-L715) (verified)
   - What this is: `runBook` calls `buildRenderGraph()`, which stores a new system driver, Piper and Kitten engine in fields.
   - Problem: a battery or charger guard pauses and later resumes; each resume builds new engines and overwrites the fields, and the old ones are only released in `onDestroy`. Native models are large (about 170 MB each per the code), so two or three charger plug cycles can kill the process on the 1.5 GB tablet.
   - Fix: one `releaseEngines()` used by `buildRenderGraph` (before building) and `onDestroy`.
   - If we skip it: long renders die with OOM or a native crash.

7. **A failed rename deletes the live manifest** (render/RenderFinalize.kt:L449-L472) (verified)
   - What this is: `atomicWriteText` writes `.tmp`, renames it over the target, and on failure deletes the target and retries 20 times.
   - Problem: the first failed rename deletes `manifest.json`; if all retries fail the `.tmp` is deleted too, so both copies are gone and the book vanishes from the library.
   - Fix: never delete the target (on Android `renameTo` already replaces it); on final failure keep the old target and delete only the temp.
   - If we skip it: a rare I/O hiccup loses a whole book's manifest.

## Should fix

8. **POST_NOTIFICATIONS never requested (Android 13+)** (AndroidManifest.xml, MainActivity.kt:L401-L407)
   - What this is: the app posts a render notification and Media3 posts the playback notification.
   - Problem: on API 33+ both are hidden until the runtime permission is granted, so Pause/Cancel and lock-screen controls are invisible.
   - Fix: declare it and request it once on API 33+, never blocking the library on a deny.
   - If we skip it: no notification controls on 13+.

9. **Notification actions can fail to restart a stopped render service** (render/RenderService.kt:L1725-L1735, L328)
   - What this is: Pause/Resume/Cancel use `PendingIntent.getService`; resume calls `startForeground`.
   - Problem: if the service was killed, tapping Resume is a background start: `IllegalStateException` on API 26+, `ForegroundServiceStartNotAllowedException` on 31+.
   - Fix: `PendingIntent.getForegroundService` on API 26+; catch the start failure in `enterForeground`, keep the job paused, stopSelf.
   - If we skip it: a resume tap can crash or silently do nothing.

10. **Content draws under the system bars on Android 15+** (MainActivity.kt:L233-L262)
    - What this is: Compose root with no inset handling.
    - Problem: targetSdk 35+ forces edge-to-edge on API 35+, so the top bar and bottom player controls sit under the status and navigation bars.
    - Fix: `Modifier.windowInsetsPadding(WindowInsets.safeDrawing)` on the root surface (no-op on old APIs).
    - If we skip it: hidden controls on 15+.

11. **Chapter JSON read has no size cap and no path check at play time** (bundle/ChapterTextLoader.kt:L44-L60, playback/PlaybackService.kt:L568)
    - What this is: the 8 MB cap and `..` check run only in the import validator.
    - Problem: a chapter file swapped or grown after import (300 MB) is read whole; `OutOfMemoryError` is not an `Exception`, so the service dies. `"text": "../x.json"` reads outside the bundle.
    - Fix: check `sizeBytes` against the same cap and reuse the audio path containment before reading.
    - If we skip it: one bad file crashes playback instead of showing an error.

12. **Big PDF or entity-bomb EPUB crashes import** (ingest/PdfText.kt:L54-L64, ingest/EpubContainerReader.kt:L465-L501)
    - What this is: on-device import of untrusted files.
    - Problem: `PDDocument.load(file)` parses the whole PDF into the heap; the XML parser allows DOCTYPE entities (billion laughs). Both end in OOM, which the `catch (Exception)` misses.
    - Fix: `MemoryUsageSetting.setupTempFileOnly()` plus a file size cap; refuse XML containing `<!ENTITY`.
    - If we skip it: a crafted or huge book kills the app with no message.

13. **Sherpa engine release races synthesis** (full/.../tts/SherpaPiperEngine.kt:L60-L97, SherpaKittenEngine.kt:L42-L78)
    - What this is: native TTS handles in plain fields, released from `onDispose` while `synthesize` may be running.
    - Problem: leaving a screen mid-audition frees the native model under a running `generate` (SIGSEGV); two concurrent loads create two handles and leak one.
    - Fix: `synchronized` around load/synthesize/release.
    - If we skip it: rare native crashes and 170 MB leaks.

14. **Spool index rewritten after every sentence, not atomically** (render/SpoolRenderer.kt:L240-L247)
    - What this is: sentence-level resume state for on-device render.
    - Problem: a 1,500-sentence chapter rewrites a growing JSON 1,500 times (hundreds of MB of writes to slow flash); a kill mid-write tears it and the whole chapter re-renders.
    - Fix: persist every 25 sentences and on stop, via the existing atomic write.
    - If we skip it: slower renders and lost resume work.

15. **Live-voice stream can restart itself forever** (playback/PlaybackService.kt:L1118-L1128) (needs a check of StreamCore)
    - What this is: `onStreamFailed` reloads the book, which restarts the same failing stream.
    - Problem: an engine that fails on every start loops: rebuild driver, wait 5 s, fail, repeat.
    - Fix: stop after 2 failures in a row (reset on the first spoken sentence).
    - If we skip it: battery drain and a repeating notice.

16. **Player import check skips the chapter `index` rule the spec requires** (bundle/BundleValidator.kt vs spec/bundle.md section 7 and scribe/bundle/validate.py)
    - What this is: the spec says the Player reuses the same checks as `scribe validate`.
    - Problem: a bundle with chapter indexes 1, 3, 4 or two entries with index 2 imports on the tablet; progress is keyed by chapter index, so resume lands on the wrong chapter. No Kotlin test runs the `parity/expected` fixtures.
    - Fix: add the consecutive-index check; add one JUnit test that runs `spec/fixtures` bad/shape bundles and compares verdicts with `parity/expected`.
    - If we skip it: the two validators keep drifting.

17. **Scribe `open-folder` launches any file** (scribe/ui/transfer.py:L435-L461)
    - What this is: the UI button opens the transfer destination in Explorer.
    - Problem: it only checks `exists()` then `os.startfile`, so a request with `C:\...\setup.exe` runs it.
    - Fix: require `is_dir()`.
    - If we skip it: a local process holding the token can run programs.

18. **Scribe helper says "ready" before it listens** (scribe/ui/helper.py:L163-L187)
    - What this is: the Rust UI waits for a ready line with the port.
    - Problem: the port is probed by bind-and-close, then printed, then uvicorn binds; another process can take it in the gap, or the UI connects before uvicorn is up.
    - Fix: bind one socket and pass it to uvicorn (`server.run(sockets=[sock])`).
    - If we skip it: intermittent "helper not reachable".

19. **SSE job stream re-reads the whole log twice a second on the event loop** (scribe/ui/app.py:L978-L1029)
    - What this is: live progress for builds.
    - Problem: cost grows with the log; on a long book every other request stalls behind it.
    - Fix: keep a byte offset and read only new bytes.
    - If we skip it: the UI freezes on big books.

20. **Rust UI helper token is guessable** (scribe-rs/scribe-ui/src/helper.rs:L141-L161)
    - What this is: the secret that guards the helper API.
    - Problem: it is an FNV hash of pid, clock and a counter; a local process can narrow it to about 2^20 guesses.
    - Fix: build 128 bits from OS-seeded `RandomState` (no new dependency).
    - If we skip it: the token gives little protection.

Left out (smaller, 12): three Room instances on one file (MainActivity/PlaybackService/RenderService), PlaybackService exported with open session, progress 0% for stream-only books, cover sniff decompressing every image, orchestrator worker failure noticed late, no handshake timeouts, Job Object race, `--results` default path, tracing on stdout, Audacity export per-sentence ffmpeg and bad label offsets, cache decode under one lock, transfer record errors swallowed.

Verdict: fix 1 to 3 first (Android 12 blockers), then 5 to 7 (security and data loss).
Not checked: reader UI screens in depth, attribution/cast logic, most of scribe/cli.py and build.py, scribe-ui main.rs; nothing run on a device or emulator; Rust tests not run (no MSVC linker at audit time).
